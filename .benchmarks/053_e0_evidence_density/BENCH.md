## The measurement

`harness --e0` (new; `src/harness/runner/e0.rs`). Per dataset suite, on the

- **seen** = the event's bucket was touched by ANY domain's training docs
  (the fit-time seen set, now retained as a 16 KiB bitset on `NbScope` —
  the same set `fit` already computed for α; duplicates counted, i.e. the
  same event stream the blend σ's `n_tokens` divides by);
- **tables** fit on the DEPLOYED corpus — the full registry pool (train

  noul polarity do not move seen-ness (they weight scores, not counts);

- **pre-declaration** (the issue's conservative form): a suite is written

## Reading (and the one caveat)

- **The density premise transfers.** Proposal 013's fusion died because the
  Go transposition tables had never seen the states; Bench 051's "the train
  split already supplies the vocabulary" was the hint, and this is its
  per-state confirmation. The H2 evidence gate `g = σ((n − n_min)/τ_n)`
  will sit at ~1 almost everywhere — so **H2's discriminating work is
  β·m_i (the margin term), not the gate**, and T3's tuning task is the
  margin scale, with the gate as a safety floor for the rare thin state
  (massive's n = 3 tail).
- **typed_decisions: density ≠ armability.** Its selection slice is the
  densest in the table (median 129, 100.0% seen/total) and Bench 051
  measured that its tables **never arm** at all — its options are
  state-field values, so route terms (and the tables' legality guard) never
  activate. E0 measures the tables-vs-states axis only; arming H2/H3 there
  needs the option-conditioned scorer first (Bench 051's recorded gap). The
  ARMED-PENDING verdict is the density fact, not an arming commitment.
- **massive_intent_en** is the thinnest (short utterances: median 9 seen
  events, 81.0% seen/total, the only n < 4 tail) — exactly where the gate
  earns its keep, and well inside it.

   mean fraction zipped the SORTED counts against the raw totals. Fixed

   at the source) and pinned by
   `seen_fraction_pairs_each_count_with_its_own_total`. Every other stat
   was order-independent and unaffected. The numbers above are the fixed
   run.

   the tool); the landing commit changes no measurement code after this
   record's table was produced — the artifacts carry the run's own sha.
3. Box state (context only — these are deterministic counts, not latency):

4. `run_e0` never arms an engine posture and reads no gold; the single
