# Issue 112: LTT risk-target threshold posture — certified abstention for the fused gate

**Status:** Open — adoption proposal, no novelty claim (the mechanism is published: Learn-then-Test, arXiv:2110.01052; its typed-decision accept-threshold application is ThinkJev, arXiv:2610.37732 §3.6; AnyJev ships the coverage-at-risk reporting view). Distilled in riir-rethink Research 018 (2026-11-07). PoC scoped below: report-only first, opt-in flag, byte-identical when off. Named house precedents to follow: Plan 615 / Bench 615 (one-sided Clopper–Pearson PAC gating, E=0 closed-form canary) and Bench 688 (`beta_union_bound`, exact-CP named as the upgrade).

## Problem

`src/engine/threshold.rs` selects the fused gate's abstain cutoff with two point-estimate postures: `Percentile { rho }` (the ρ-quantile of cal scores — the shipped arena/ESC posture) and `TargetAccuracy { target }` (lowest cutoff whose cal above-cutoff accuracy meets the target, else `TargetUnmet`). Both disclose realized cal accuracy, but neither carries a **finite-sample guarantee on the accepted subset**: a target met on a few dozen cal rows says nothing statistical about the future error rate of the answers the gate lets through. Serving law here is abstention-first; the missing piece is a certificate the caller can quote: "of the answers this threshold accepts, at most α are wrong, with probability ≥ 1−δ". Learn-then-Test provides exactly that without training, and cheaply: scan candidate cutoffs strictest→loosest, test each with a one-sided Clopper–Pearson upper bound on the accepted-subset error at level δ, stop at the first failure (fixed-sequence testing → no multiplicity correction), adopt the loosest passing cutoff. ThinkJev §3.6 is the worked recipe on typed decisions, including the two disciplines our implementation must inherit: the sample unit is independent GROUPS (template/variant duplicates count once), and the honest expectation table — at α=1% nothing certifies below ~hundreds of accepted groups; even at α=5% a strong 27B floor certifies only 24.5% of decisions (at 3.9% realized). The value on our cal-slice sizes is mostly the loud "none certified" disclosure, not coverage wins — that is the deliverable, pre-registered.

## Task

- [ ] **T1 — `Posture::RiskTarget { alpha, delta }`** in `src/engine/threshold.rs`: over a PRE-REGISTERED FIXED GRID of candidate cutoffs (v1: 1000 evenly spaced points in [0,1] over the calibrated score — the candidate set must be fixed before the data is inspected, or the fixed-sequence guarantee's premise breaks; a cal-derived grid would test hypotheses chosen by the data), scan strictest→loosest; at each, one-sided Clopper–Pearson UPPER bound on the accepted-subset error at level `delta`; take the LOOSEST passing candidate; stop at the first failure. When no candidate passes (or T2's floor refuses), return the honest not-certified state — NEW `RecommendationStatus::NotCertified` (additive variant; do NOT reuse `TargetUnmet`: a met target without a guarantee and a failed certification are different disclosures). Never fall back silently to a point-estimate cutoff: when not certified, which geometry answers stays the caller's (the percentile fit's) business.
- [ ] **T2 — Group unit + zero-error floor.** The guarantee needs independent groups; v1 group = the cal case (one decision = one group — our cal slices carry no template families today; disclose that this is conservative ONLY against a duplicate-ful slice, and name the limitation). A candidate may pass only when accepted groups `n ≥ ceil(ln(delta)/ln(1−alpha))` (the zero-error pass open — CEIL, never approx: 59 at α=5%, 299 at α=1%, δ=0.05; pin BOTH values in a test) — below it, `NotCertified` with the floor named in the disclosure. Existing `THIN_SUPPORT_FLOOR` semantics stay intact.
- [ ] **T3 — Stats source: substrate-first.** katgpt-core does NOT export an exact CP bound today: `cp_upper` is a PRIVATE fn inside the bench file `crates/katgpt-core/benches/bench_615_two_fidelity_bai_goat.rs:1031` (verified 2026-11-07), and `certified_frontier.rs` exports only the closed-form `beta_union_bound` (its own doc names the exact CP/Beta-quantile as the upgrade). **T3a (first step):** file a katgpt-rs issue to export a one-sided Clopper–Pearson UPPER bound from katgpt-core (feature-gated alongside `certified_frontier`, reusing the Bench-615 bisection + E=0 closed form as the seed implementation + canary). **T3b:** until that export lands, a reflex-local bisection is a RECORDED TEMPORARY DEVIATION (substrate-first consumed-as-issue, not a silent fork): cite the Bench-615 precedent line in the module doc, name `delta` and the interval identity, pin the E=0 closed form `cp_upper(0, n) = 1 − delta^(1/n)` in a test, and mark the local fn `// TEMPORARY: superseded by the katgpt-core export (T3a)` so the deviation is greppable and retired when the export lands.
- [ ] **T4 — Harness lever, report-first:** `--gate-risk-target <alpha>` (`delta` pinned 0.05 in v1, disclosed; opt-in, byte-identical when off). Pre-registered gates, BEFORE running — note the guarantee's own shape sets the pass bars: LTT bounds the error at probability 1−δ, NOT surely (the ThinkJev record itself contains a realized 10.5% > 10% violation on Qwen3.8-27B), so per-suite point-estimate failures are expected noise and must not read as a broken posture:
  - (a) **CERTIFICATE (statistical, not pointwise):** per suite where coverage > 0, pass when the realized TEST error's exact binomial interval is CONSISTENT with the target — the LOWER end ≤ alpha (a point estimate above α whose interval still contains α reads as the 1−δ noise it is, disclosed, never auto-failed); across suites, the BREACH BUDGET is pre-registered — **breach = LOWER binomial end > alpha**, a CONFIDENT violation (the whole interval above the target — exactly the per-suite pass rule's failure, so T4(a) and T6 are ONE test read from both sides). The UPPER end is NOT the breach event: on small slices the upper end clears α almost always even when the posture is correct and the true error is well below it (the paper's own Qwen3.8-27B row at α=10% — realized 10.5%, interval [9.5, 11.7] — is per-suite noise, lower end 9.5 ≤ 10, and counting it via the upper end was the round-2 draft's error). Each certified suite breaches with probability ≤ δ = 0.05 (the guarantee's own level), so on the harness's suite count N the expected breaches are δ·N (≤ 0.5 at N ≤ 10) — **2 or more lower-end breaches on ≤ 10 suites is the pre-registered line for "the posture is wrong"** — meta-test α ≈ 8.6% at N=10 is the δ-ONLY approximation; with the test interval's own one-sided tail (~2.5% for a two-sided 95% interval) each suite breaches at ≤ δ + tail ≈ 0.075, putting P(≥2 breaches | correct) at up to ~17% — the "≥2 means wrong" line stands, and 1 breach is within the guarantee's own probability mass and is disclosed, not failed.
  - (b) **HONESTY (property test, holds by construction):** with target = 1−alpha, RiskTarget coverage ≤ TargetAccuracy coverage — because a CP-passing cutoff's accepted point error ≤ alpha (the CP upper bound never undercuts the observed rate) implies it also passes TargetAccuracy's point-accuracy screen, so the certificate-passing set is a SUBSET of the accuracy-passing set and its loosest member is at least as strict. Pin this as a property unit test on synthetic slices, never an empirical gate.
  - (c) **FALSIFICATION (the arms a correct certificate must FAIL):** replacing the cal/test-half swap (same-suite halves share one distribution — LTT SHOULD survive that swap, so it tests nothing): **(c1) shuffled labels** — permute the correctness labels so accepted-subset error ≈ the base rate; the posture must return `NotCertified` for every alpha below that base rate; **(c2) planted violation** — a synthetic cal slice whose accepted-subset error exceeds alpha must not certify at that alpha; **(c3, report-only)** cal from one suite + test from another as a DISTRIBUTION-SHIFT REPORT ROW (the guarantee's exchangeability premise is broken there — record what happens, never a pass/fail gate).
  - Report-only in this issue; wiring into any serving posture is a separate owner-gated step.
- [ ] **T5 — Wire-compat caveat (additive-only law):** `Posture` is serde-tagged; old readers fail on unknown enum variants. The posture is opt-in and produced only when the lever arms, so no default run ever emits it — assert that in a test (no shipped posture writes RiskTarget metadata), and flag the contract-version question explicitly if a persisted artifact ever needs to carry it.
- [ ] **T6 — Expectations (pre-registered, honest):** strict α certifies ~nothing at our cal-slice sizes — the loud "none certified" is the EXPECTED outcome at our group counts, never a failure. The posture is wrong iff T4(a)'s breach budget fires (≥2 LOWER-end breaches on ≤10 suites) or a falsification arm CERTIFIES where it must not (c1/c2); either closes the issue NEGATIVE (fix first if the defect is in the implementation rather than the method). A second negative probe is an acceptable close (the Issue 107 precedent).
