# Issue 081 — Jev-Mem System-One backend lane (reflex as a memory-control decision backend)

**Status:** OPEN — measurement lane (Research 310, ndb; arXiv:2609.23986). Decision-layer cells are free + local; LoCoMo end-to-end needs an answer model (owner-gated spend, BYO-key posture like the Proposal-014 lane-3 shape).

Jev-Mem (`libingzheren/Jev-Mem`, MIT, @ `7ab0c73c`) is the first published system that runs an ENTIRE memory lifecycle on a typed decision engine — and its System-One backend is **pluggable**: TypeSafe Jev API is the default, local Laya was added 2026-09-27 in one commit (`memory/laya_backend.py`, `config/laya_mem.json`). The backend interface is small: `client.evaluate(operation, state, questions{Noul|Choice}, mock_values, budget)` — every question maps 1:1 onto `decision_wire` (`noul` = Noul, `choice` = Choice with criteria). Their question inventory (admission/typing/relations/consolidation/routing/stopping/traversal, ~25 noul + 2 choice) is a ready-made **memory-control decision pack**.

Why it matters for reflex: the arena thesis extends from datasets to APPLICATIONS — a live third arena where the modelless engine + calibration surface competes for the controller slot of a published memory system. Their paper's honest caveat ("model-reported values are not assumed to be calibrated probabilities") is exactly our `SigmoidGateCalibrator` + conformal-floor differentiator.

  - 2026-10-09 design note (read from their tree @ `7ab0c73c` + the `typesafe_sdk` 0.7.2 wheel): **the integration is ZERO-FORK** — `JevMemConfig.load` honors `TYPESAFE_BASE_URL` → `jev_base_url`, and `decision_backend="jev"` (their default) sends their own `TypeSafeClient.system_one()` at whatever base URL the env names. So the adapter is NOT a python backend class (the `LayaBackend` shape) — it is a **native `/v1/systemone` route in `reflex serve`** speaking the TypeSafe wire (SDK `SYSTEM_ONE_PATH = "/v1/systemone"`; body `{state, model, questions{qid: {type: noul|choice|score, instructions?, criteria?}}}`; noul criteria `{true,false}`, choice criteria `{label: desc|null}` ordered, score criteria `[desc...]` from zero; response `{model, usage, answers{qid}}` with NoulAnswer `{type,noul}`, ChoiceAnswer `{type,choice,confidence,probabilities}` (sum≈1 ± 1e-3, choice MUST be argmax), ScoreAnswer `{type,score,confidence,legend,probabilities}` keyed by int). Jev-Mem plugs in with THREE env vars: `decision_backend=jev` (their default config), `TYPESAFE_BASE_URL=http://127.0.0.1:7331`, `TYPESAFE_API_KEY=reflex-local` (dummy — our route never checks it). Translation: noul criteria render into `Question.criteria` (the engine ctx = prompt + criteria); choice criteria keys → options (insertion order, serde_json preserve_order) + descriptions → criteria string; state → canonical JSON string. Abstain mapping (the TypeSafe wire has NO abstention): noul → `noul: 0.5`; choice → uniform probabilities + deterministic argmax(tie→first) — the laws their `_validate` enforces (sum ±1e-3, argmax consistency) are pinned as gates. usage `{}` (the modelless engine counts no tokens — the honest `generated_tokens: 0` posture). Their call map (7 operations, all via `JevClient.evaluate`): `observation` (9 noul), `memory_type` (4 noul), `relations` (3-4 noul × candidate), `consolidation` (4 noul + 1 choice × candidate), `routing` (6 noul), `stopping` (4 noul), `traversal` (4 noul × candidate). The demo hardcodes `jev_mock=True` — the E2E driver mirrors `jev_mem/demo.py` with `jev_mock=False` (a local driver script, nothing contributed upstream).
