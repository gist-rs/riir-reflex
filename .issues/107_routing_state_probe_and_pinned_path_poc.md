# Issue 107: routing-state probe + pinned-path replay PoC (Research 014 / arXiv:2611.03526)

**Status:** OPEN — PoC with pre-registered gates; T1 is diagnostic-first (completes Bench 167's MI finding with a supervised bound), T2 is report-only pin replay; NO serving-path change anywhere in this issue
**Lease:** none needed — fresh filing (Research 014 same session)

**Distill:** [Research 014](../.research/014_Library_of_Layers_Routing_State_Probe_Pin.md) (LoL, arXiv:2611.03526) — the two closed-form runtime halves of a trained router (supervised probe over routing state; mode-path extraction + forcing), transferred to reflex's `pick_domain` engine. Published prior art occupies the probe-as-side-channel class ([arXiv:2610.07774](https://arxiv.org/abs/2610.07774) — router-logit safety detector read at prefill); this issue claims NO novelty — it measures whether the mechanism carries signal on OUR routing features and whether the pin half is worth a seam. **Internal prior negative carried:** reflex [Bench 157](../.benchmarks/157_depth_probe_n100.md) recorded depth-as-CONFIDENCE NEGATIVE (residual-stream stability → correctness ≈ chance on 6/9 suites) — a DIFFERENT feature source (residual stream, not routing state); this issue is not a Bench 157 re-run, but any probe result here must be read against that negative.

## Why here (the coverage gap, one paragraph)

Bench 167 measured routing-state→gold UNSUPERVISED (MI: banking77 5.59 bits ≈ routing is a classifier there; ag_news 0.14 / emotion 0.28 bits ≈ it is not) with a `Scratch::forced_domain` one-shot counterfactual seam. LabelHeads/NbRidge fit supervised readouts over CONTENT features (hashed bags), never over the routing state. The unshipped, measurable pair: (T1) a supervised linear probe over routing-state features — the supervised bound over the MI numbers; (T2) extraction of an inference-keyed mode path from recorded selections + a report-only forced-path replay — the persistent-policy half the Bench 167 seam deliberately does not have. Both run on the existing harness instrument set (cal slices, frozen read, determinism witness).

## Phase 1 — supervised probe over routing-state features (T1)

- [ ] **T1.1** Capture routing-state features per case on the seated suites. TWO arms with different status: **(a) score-vector arm — MANDATORY** (the per-domain pick scores the router computes before argmax; this is the only arm that can carry information BEYOND Bench 167's MI, because a one-hot routed domain makes the probe a lookup table p(label | domain) whose accuracy is already bounded by the measured MI). If the engine cannot expose the score vector without a forward change, STOP the whole issue at T1.1 and record why — the one-hot-only probe is not worth running. **(b) one-hot arm — consistency check only** (it MUST agree with the MI-implied bound; agreement is the deliverable, not a finding).
- [ ] **T1.2** Closed-form ridge (mirror `nb_ridge`'s solve shape; λ swept over a fixed grid) fit on the cal slice → held-out label AUROC/accuracy per suite, ONE frozen read. **AUROC definition, pre-registered BEFORE the frozen read: macro one-vs-rest** (mean of per-class one-vs-rest AUROC over the suite's classes; per-class tail support printed — a class with < 10 positives is UNDECIDABLE and excluded from the macro mean with its exclusion named). Pre-registered gates: banking77 probe accuracy must land within 2σ of its routed accuracy (MI already predicts near-perfect — the gate proves the probe doesn't UNDERREAD the MI signal); ag_news/emotion AUROC reported with tail support (`n_pos`/`n_neg` printed; a suite with thin support is UNDECIDABLE, never folded into a pass). Degenerate-feature loud-fail: a suite whose routing features are (near-)constant must FAIL the probe loudly, never score ~0.5 silently.
- [ ] **T1.3** Calibration discipline: any claim phrased as calibrated carries the conformal-naive floor per the standing UQ rule; the default claim is AUROC-only (discrimination, not calibration), so the floor applies only if a threshold/abstention consumer is proposed.
- [ ] **T1.4** Verdict row in the bench record: per-suite probe-vs-MI agreement (the MI number PREDICTS the probe bound — do they agree?). Disagreement (probe ≪ MI-implied bound) is itself the finding (the signal is non-linear) and is reported, not buried.

## Phase 2 — mode-path extraction + report-only pinned replay (T2)

- [ ] **T2.1** Extract mode paths from recorded harness runs: per routed position, argmax of the mean selection over labeled cases → frozen table (here D degenerates to the single routing level the engine has). **The table's KEY is inference-available information ONLY** — suite id, or T1's probe-predicted class — never the gold label (LoL forces a caller-DECLARED strategy; a gold-keyed pin leaks the label at inference). Bit-identical re-extraction from the same log (digest test). A per-SUITE-keyed table is a CLASS-BLIND constant pin (every case of the suite forced to one domain) — that is a named baseline shape, reported as such; the interesting keyed variant uses T1's predicted class as the key.
- [ ] **T2.2** Forced-path replay through the EXISTING `forced_domain` seam (report-only, harness posture only), two separate readouts that are never pooled: **(a) inference-keyed pins** (suite-keyed constant + T1-predicted-class-keyed): paired accuracy live-vs-pinned per suite + adherence rate, gated on paired NON-INFERIORITY (LB95 > −δ). Expected shape, pre-registered: suite-keyed constants regress on banking77-class suites (the class signal dies — MI 5.59 bits means the routed domain IS the class there); predicted-class-keyed pins can at best match live routing (the pin replays what the probe predicts, so its ceiling is the probe's accuracy — name that ceiling in the readout). **(b) gold-keyed replay — ORACLE CEILING ONLY**, explicitly labeled as leakage-bound in every render; it bounds what a perfect classifier-keyed pin could achieve and is NEVER a non-inferiority result.
- [ ] **T2.3** NO promotion: the forced-domain seam stays disarmed on production paths exactly as Bench 167 left it. If T2 shows a worthwhile deterministic-replay posture, the follow-up (a named, gated, byte-identical-when-off seam) is a NEW issue, not this one.

## Out of scope (audited in Research 014 §3)

Safety-attribute suites (no labeled corpus in the harness; fabricating one is the 2610.07774 paper's world, not ours today); multi-depth library routing (no LoL-shaped weights); K3 checkpoint probing (katgpt-rs Bench 969 already answered the unsupervised half; the supervised arm there rides a test-arch checkpoint with LOW MI — weak signal, no consumer); refine-side campaign-row probing (tabular-on-logs, adopts only if this PoC passes).
