## 1. The typed question envelope

### 1.1 Question types

`laya/common.py:11`:

```python
QTYPES = {"choice": 0, "score": 1, "noul": 2}
QTYPE_NAMES = {v: k for k, v in QTYPES.items()}
```

A question definition is `{"type": ..., "instructions": str, "criteria": ...}` where
`criteria` is a **dict for choice** (`option_key -> description|None`), a **list for
score** (level descriptions, index = score value), and **absent for noul** (or a
`{"true": ..., "false": ...}` dict for descriptions).

### 1.2 Normalization to internal form

`bench_local.py:44-50` (identical in notebook cell 8 `to_internal` and
`agent.py:254-263`):

```python
def to_internal(qdef):
    t = qdef["type"]
    crit = qdef.get("criteria")
    if t == "choice" and isinstance(crit, list):
        crit = {c: None for c in crit}
    ins = qdef["instructions"]
    return {"t": t, "ins": ins if isinstance(ins, str) else json.dumps(ins), "crit": crit}
```

Non-string instructions become `json.dumps(ins)` (default separators). A
choice-criteria LIST becomes `{c: None}` **in list order** — Python dicts keep
insertion order, and option order below follows dict iteration order.

### 1.3 State serialization

`laya/common.py:15-18`:

```python
def serialize_state(state) -> str:
    if isinstance(state, str):
        return state
    return json.dumps(state, ensure_ascii=False)
```

`json.dumps` with **default separators `(", ", ": ")`** (Python's default when
`indent=None`), `ensure_ascii=False` (raw UTF-8), keys in **insertion order**.
A state that arrived as a JSON string is used AS-IS; a state that was parsed to a
dict is re-serialized with the exact settings above. The Rust port's JSON
serializer must emit `{"k": v, "k2": v2}` with a space after `:` and `,` — Python
`json.dumps` spacing — and preserve key order.

### 1.4 Option rendering (the text after each `[MASK]`)

`laya/common.py:21-46`:

```python
def render_criterion(value) -> str:
    if isinstance(value, str):
        return value
    return json.dumps(value, ensure_ascii=False, separators=(", ", ": "), default=str)

def render_options(q) -> List[str]:
    """Render option texts in label-index order. Noul is always [false, true]."""
    t, crit = q["t"], q.get("crit")
    if t == "choice":
        # only None/"" mean "no description"; 0 and False are legitimate criterion values
        return [k if v is None or v == "" else "%s: %s" % (k, render_criterion(v)) for k, v in crit.items()]
    if t == "score":
        return ["level %d: %s" % (i, render_criterion(c)) for i, c in enumerate(crit)]
    crit = crit or {}
    false_crit, true_crit = crit.get("false"), crit.get("true")
    return [
        "false: " + (render_criterion(false_crit) if false_crit not in (None, "") else "no, the statement does not hold"),
        "true: " + (render_criterion(true_crit) if true_crit not in (None, "") else "yes, the statement holds"),
    ]
```

Critical facts: noul option order is **always `[false, true]`** (index 0 = false,
1 = true) regardless of criteria dict key order; a missing/empty noul criterion
falls back to the fixed default phrases; structured criteria render as JSON with
`separators=(", ", ": ")`.

### 1.5 Token sequence construction

`laya/common.py:49-86` (`build_sequence`). Format string from the docstring:

```
[CLS] <type> instructions [SEP] [MASK] opt0 [MASK] opt1 ... [SEP] state [SEP]
```

Exact algorithm:

```python
mask_tok = tok.mask_token
opts = render_options(q)
order = option_order if option_order is not None else list(range(len(opts)))
ins = str(q["ins"]).replace(mask_tok, " ")
head_ids = tok("%s question: %s" % (q["t"], ins), add_special_tokens=False)["input_ids"]
opt_ids = []
for i in order:
    opt_ids.append(
        [tok.mask_token_id]
        + tok(" " + opts[i].replace(mask_tok, " "), add_special_tokens=False)["input_ids"][:48]
    )
opt_budget = head_max_len - sum(len(o) for o in opt_ids)
if opt_budget < 16:
    per = max(4, (head_max_len - 16) // max(1, len(opt_ids)))
    opt_ids = [o[:per] for o in opt_ids]
    opt_budget = head_max_len - sum(len(o) for o in opt_ids)
head_ids = head_ids[: max(8, opt_budget)]
ids = [tok.cls_token_id] + head_ids + [tok.sep_token_id]
markers = []
for o in opt_ids:
    markers.append(len(ids))
    ids.extend(o)
ids.append(tok.sep_token_id)
room = max(0, max_len - len(ids) - 1)
st = tok(serialize_state(state).replace(mask_tok, " "), add_special_tokens=False)["input_ids"]
st = st[-room:] if truncate_left else st[:room]
ids = ids + st + [tok.sep_token_id]
return ids[:max_len], [m for m in markers if m < max_len]
```

Facts the port must match:
- head text = `"{qtype} question: {instructions}"` — note the literal ` question: `
  joiner and that `qtype` is the **string** (`"choice"` / `"score"` / `"noul"`).
- each option tokenized with a **leading space** and truncated to **48 tokens**
  (after the mask token id).
- token budget law: `head_max_len` (192 laya / 256 multilingual+typed) covers
  instructions + all options; fallback when `opt_budget < 16` gives each option
  `max(4, (head_max_len-16)//n_opts)` tokens; head keeps `max(8, opt_budget)`
  tokens.
- state budget `room = max_len - len(ids) - 1`; state is **head-truncated**
  (`st[:room]`; `truncate_left=False` in every bench path).
- `max_len` (512 laya / 1024 multilingual+typed) is a hard final clamp
  (`ids[:max_len]`), and markers with position ≥ max_len are dropped.
- all tokenizer calls use `add_special_tokens=False` — CLS/SEP/MASK are inserted
  manually; the only tokenizer-specific ids are cls/sep/mask/pad.

### 1.6 Batched inference (does not change per-sequence results)

`bench_local.py:53-97` (`score_cases`, CPU: `max_tokens=8192, max_seqs=64`) and
notebook cell 8 (CUDA: `max_tokens=16384, max_seqs=128`). Every question of every
case is ONE sequence; valid sequences are sorted by length and packed greedily
into token-budgeted batches (`max(L, len) * (j-i+1) <= max_tokens`). Returns
**UNCALIBRATED logits** per question (`out[idx] = logits[r, :k]`, cast float32);
temperature is applied later so raw/calibrated come from one forward pass.

A question is DROPPED (index entry keeps `(ci, qid, qtype, 0)`, logits `None`,
excluded from all metrics) when `build_sequence` raises OR
`len(markers) != len(render_options(q))` — the head-budget overflow case
(`agent.system_one` raises `ValueError` here instead;
`agent.py:287-288`). Recorded runs had `dropped: 0` everywhere.

### 1.7 The answer envelope (`system_one`)

`agent.py:322-368` — per question, with `t_scale = temperature_by_options.get(
temp_bucket(qt, k), temperature[qt])`, `z = logits[:k] / t_scale`, stable softmax:

```python
conf_score = round(confidence_from_probs(p, k), 4)          # 1 - H(p)/log(k), clipped [0,1]; k<2 -> 1.0
ext = {"act_probability": round(float(act[r, 0]), 4)}
# choice  -> {"type": "choice", "choice": keys[argmax], "probabilities": {key: round(v,4)},
#             "confidence": conf_score, "action": ext}
# score   -> {"type": "score", "score": round(sum(arange(k) * p), 4),
#             "legend": {str(i): c}, "probabilities": {str(i): round(v,4)},
#             "confidence": conf_score, "action": ext}
# noul    -> {"type": "noul", "noul": round(p[1], 4),
#             "confidence": round(max(p[1], 1-p[1]), 4), "action": ext}
```

Note the noul confidence is `max(p_true, 1-p_true)` — NOT the entropy confidence —
while choice/score use `confidence_from_probs` (`laya/common.py:210-216`).

## 2. Temperature / calibration handling

### 2.1 Buckets

`laya/common.py:219-221`:

```python
def temp_bucket(qtype: int, k: int) -> str:
    size = "2" if k <= 2 else "3-5" if k <= 5 else "6-10" if k <= 10 else "11+"
    return "%s:%s" % (QTYPE_NAMES[int(qtype)], size)
```

### 2.2 Application (the bench path)

`bench_local.py:100-107`:

```python
def softmax_t(z, t=1.0):
    z = np.asarray(z, float) / max(1e-3, float(t))
    e = np.exp(z - z.max())
    return e / e.sum()

def temp_for(agent, qt, k):
    return float(agent.temperature_by_options.get(temp_bucket(qt, k), agent.temperature[qt]))
```

**Clamp at load (`agent.py:206-210`, `laya/common.py:228-240`):** shipped

→ 1.0) before use. The English checkpoint ships

## 3. Task protocols

Each task = a list of `(state, {qid: qdef})` cases + per-question gold. Cases are
built ONCE with the fixed seed and reused byte-identically for every checkpoint
("Both models see byte-identical questions (fixed seed)" — notebook cell 0).

### 3.1 typed-decisions (400 cases / 2,000 decisions)

**Dataset:** `LocalLLaMA/typed-decisions`, config `"all"`, split `"test"`
(notebook cell 12) — the repo-local CPU harness reads the same rows from a parquet:
`REPO/typed-decisions/all/test-00000-of-00001.parquet` via
`pd.read_parquet` (`bench_local.py:221-224`). **ALL 400 rows — no sampling, no
row RNG.**

**Row schema:** `workflow` (string), `state` (JSON string — parsed with
`try: json.loads`), `questions` (JSON string of `{qid: qdef}`), `gold`
(JSON string of `{qid: {...}}`).

```python
questions = json.loads(r["questions"]) if isinstance(r["questions"], str) else r["questions"]
gold = json.loads(r["gold"]) if isinstance(r["gold"], str) else r["gold"]
state = r["state"]
try: state = json.loads(state)
except Exception: pass
```

**State envelope:** one `state` per case carrying the case's question set. 400
cases × 2,000 questions; **per-type totals (measured from the T4 run's
`by_question_type`): choice 600, score 800, noul 600** — i.e. ~5 questions per
case on average but NOT a fixed 5-per-case template; the exact per-case set is
whatever the row's `questions` field holds. 4 workflows (the row's `workflow`
column): agent trace observability, customer service, invoice processing,
security incidents. Question iteration order within a case = the parsed dict's
insertion order (this order feeds the calibration fit/held split, §4.2).

**Gold mapping** (notebook cell 12; `bench_local.py:233-247` is equivalent):

```python
for qid, qdef in questions.items():
    g = gold[qid]
    if qdef["type"] == "choice":
        keys = list(qdef["criteria"].keys())
        gmap[qid] = {"idx": keys.index(str(g["label"])), "keys": keys,
                     "soft": [float(g.get("probabilities", {}).get(k, 0.0)) for k in keys]}
    elif qdef["type"] == "noul":
        idx = 1 if str(g["label"]).lower() == "true" else 0
        pt = float(g.get("probabilities", {}).get("true", g.get("noul", 0.5)))
        gmap[qid] = {"idx": idx, "keys": ["false", "true"], "soft": [1-pt, pt]}
    else:  # score
        n = len(qdef["criteria"])
        gmap[qid] = {"idx": int(g["label"]), "keys": [str(i) for i in range(n)],
                     "soft": [float(g.get("probabilities", {}).get(str(i), 0.0)) for i in range(n)],
                     "gold_score": float(g.get("score", float(g["label"])))}
```

- **choice:** gold index = position of `str(gold.label)` in the criteria KEY order
  as stored in the dataset (never shuffled here).
- **noul:** label `"true"` (case-insensitive) → idx 1; soft target
  `[1-p_true, p_true]` where `p_true = probabilities["true"]` else `gold.noul`
  else **0.5**.
- **score:** idx = `int(label)`; soft target over `"0".."n-1"` keys;
  `gold_score = float(gold.score)` else `float(label)`.

**Scoring (see §5):** hard metrics calibrated+raw; soft metrics
(`soft_acc`, `brier_soft`, `tv`, `kl`) and score metrics (`score_mae`,
`within_1`) computed on the **calibrated** probabilities, gold soft normalized
to sum 1 first.

The published headline (BENCHMARKS.md): typed-decisions ckpt 0.766 / soft 0.471
/ Brier 0.061 / ECE 0.213 / score MAE 0.242; base checkpoints ~0.36 (below the
0.461 majority-class baseline).

## 4. Special protocols

### 4.1 Option-order robustness (notebook cell 24)

Suites: `massive_intent.en`, `en.emotion`, `xnli.en`. Per (model, suite):

```python
base = S["cases"][:200]                  # FIRST 200 cases of the suite
rng = random.Random(99)                  # fresh per model+suite
for state, questions in base:
    qid = list(questions)[0]; qdef = questions[qid]
    keys = list(qdef["criteria"].keys())
    order = list(range(len(keys))); rng.shuffle(order)
    newcrit = {keys[i]: qdef["criteria"][keys[i]] for i in order}   # same items, permuted INSERTION order
    perm_cases.append((state, {qid: {**qdef, "criteria": newcrit}}))
# compare RAW (untemperatured) logits:
flip if keys[int(np.argmax(za))] != pkeys[int(np.argmax(zb))]
out[sname] = {"n": compared, "flip_rate": round(flips / max(1, compared), 4)}
```

The permutation reorders the criteria dict's insertion order (which IS the option
order); the comparison maps argmax positions back to key NAMES on both sides.
`n` counts pairs where both logits are non-None.

### 4.2 Calibration repair (notebook cell 26)

Per (model, suite) with ≥ 60 (logits, gold) pairs:

1. Split the suite's pairs **in index order** (case order × in-case question
   order): `fit_set = pairs[:half]`, `held = pairs[half:]`, `half = len(pairs)//2`.
2. Bucket fit pairs by `temp_bucket(qt, k)`; fit one temperature per bucket with
   **≥ 25 pairs** via grid search minimising NLL —
   `np.geomspace(0.2, 10.0, 160)`, `best_t` rounded to 4 decimals
   (`fit_temperature`, cell 8).
3. On held pairs: `rows_ship` uses the shipped temperature; `rows_fit` uses
   `fitted.get(bucket, shipped)`. Report `hard_metrics` on both:
   `{n_heldout, fitted_temperatures, ece_shipped, ece_refit, nll_shipped,
   nll_refit, accuracy}` per suite, plus `mean_ece_shipped` / `mean_ece_refit`
   (unweighted mean over suites, rounded 4).

### 4.3 Matched context control (notebook cell 20)

`typed_decisions_matched_512`: re-run typed-decisions with BOTH checkpoints'

## 5. Metrics definitions (port verbatim)

### 5.1 Hard metrics — notebook `hard_metrics` (cell 8; UNROUNDED floats in the T4 JSON)

Input `rows = [(gold_idx, probs)]`, `None` probs dropped first:

```python
gold = np.array([g for g, _ in rows]); pred = np.array([int(np.argmax(p)) for _, p in rows])
conf = np.array([float(np.max(p)) for _, p in rows]); corr = (pred == gold).astype(float)
{"n", "accuracy" = corr.mean(),
 "macro_f1":  # classes = sorted(set(gold) | set(pred)); F1_c = 2tp/max(1, 2tp+fp+fn); mean over classes
 "ece":  ece_score(conf, corr),          # 15 equal bins over (0,1]; bin weight * |mean_conf - mean_acc|
 "brier": mean(sum((p - onehot(g))**2)), # multi-class (sum over ALL classes), one-hot size = len(p) of THAT question
 "nll":  mean(-log(max(p[g], 1e-12))),
 "aurc": aurc(conf, corr),               # mean over prefix lengths of cumsum(1-corr)[conf-descending] / rank
 "mean_confidence": conf.mean(),
 "acc_at_50_coverage": corr[np.argsort(-conf)[:max(1, int(len(conf)*0.5))]].mean(),
 "acc_at_80_coverage": corr[np.argsort(-conf)[:max(1, int(len(conf)*0.8))]].mean()}
```

ECE (`laya/common.py:197-207`, identical in both scripts): bins = 15,
`np.linspace(0, 1, 16)` edges, membership `(conf > lo) & (conf <= hi)` —
**left-open, right-closed**; empty bins skipped; empty input → NaN.

bench_local's `metrics()` (`bench_local.py:132-144`) is the same metrics
ROUNDED to 4 decimals, with `acc_at_50_coverage` only (cut = `max(1, len//2)`),
no `aurc`/`acc_at_80`, plus `"n": 0` short-circuit on empty input.

### 5.2 Soft-distribution metrics (typed-decisions only; notebook cell 18)

Computed on **calibrated** probs `p_cal` against the normalized gold soft target:

```python
gp = np.asarray(g["soft"], float)
if gp.sum() > 0:
    gp = gp / gp.sum()
    pp = p_cal[:len(gp)] if len(p_cal) >= len(gp) else np.pad(p_cal, (0, len(gp)-len(p_cal)))
    pp = pp / max(pp.sum(), 1e-12)
    soft_acc   = (pp * gp).sum()                      # probability the model puts on gold under soft truth
    brier_soft = ((pp - gp) ** 2).sum()
    tv         = 0.5 * np.abs(pp - gp).sum()
    kl         = (gp * np.log(np.clip(gp / np.clip(pp, 1e-12, None), 1e-12, 1e4))).sum()
```

Reported as the mean of each accumulator (T4 JSON fields `soft_acc`, `brier_soft`,
`tv`, `kl`; bench_local names them `soft_accuracy` / `brier_vs_soft`, rounded 4,
and omits tv/kl).

### 5.3 Score metrics (score-type questions)

```python
exp = float((np.arange(len(p_cal)) * p_cal).sum())     # expected level under calibrated probs
score_mae  = abs(exp - g["gold_score"])
within_1   = float(abs(exp - g["gold_score"]) <= 1.0)
```

(bench_local names it `within_1_level`, same `<= 1` predicate.)

## 7. Byte-compatibility notes for the Rust port

1. **Python `random` must be reproduced exactly** — three tasks consume RNG and
   the option order determines the gold index, so any drift changes every gold:
   - generator: MT19937, seeded via `init_by_array` on the 32-bit words of the
     seed (`random.Random(13)` → key `[13]`);
   - `rng.sample(pool, k)`: CPython's algorithm — `setsize = 21; if k > 5:
     setsize += 4 ** ceil(log(k*3, 4))`; if `n <= setsize` use the
     pool-swap loop (`j = _randbelow(n-i); result[i] = pool[j]; pool[j] =
     pool[n-i-1]`), else the selected-set rejection loop. For MASSIVE
     (n=60, k=19): `setsize = 21 + 4**ceil(log(57,4)) = 21+64 = 85 ≥ 60` → the
     **pool** algorithm. For n=20-label tasks k=19 → same.
   - `rng.shuffle(x)`: Fisher-Yates downward — `for i in reversed(range(1, n)):
     j = _randbelow(i+1); swap(x[i], x[j])`.
   - `rng.choice(seq)` = `seq[_randbelow(len(seq))]`.
   - `_randbelow(n)`: `k = n.bit_length(); r = getrandbits(k); while r >= n:
     r = getrandbits(k)`; `getrandbits(k)` takes the top bits of MT19937 outputs
     in CPython's word order (genrand_uint32 >> (32 - w) per word, words
     little-endian in the composite).
2. **`json.dumps` defaults**: separators `(", ", ": ")`, `ensure_ascii=False`,
   insertion key order. Python floats use repr-shortest round-trip — Rust's
   `serde_json` matches for f64 shortest-roundtrip, but avoid exponent-format
   differences on extreme values.
3. **Python `round()` is banker's rounding** (half-to-even); `round(x, 4)` in
   result records must match.
4. **`np.percentile`** (latency) uses linear interpolation between order
   statistics.
5. **`np.argsort(-conf)`** in `acc_at_*_coverage`/`aurc` is numpy's default
   quicksort — NOT stable on confidence ties. Ties are rare with continuous
   confidences but the port should pick a documented tie rule (recommend
   stable sort by descending conf, original order for ties) and note it.
6. **`bench_apps` suites share ONE `random.Random(13)` stream consumed in
   build() registration order** — phishing shuffle → jailbreak shuffle →
   toxicity shuffle → RAG `choice` per case → routing shuffle. Reordering the
   suites changes every sampled case downstream. Support triage and enron
   consume nothing.
7. **Temperature clamping at load** ([0.5, 5.0]) is part of the protocol — the
   published `laya` numbers used choice:11+ = 0.5, not the shipped 0.10058.
8. **Drop rule**: a question whose options overflow the head budget is DROPPED
   (logits `None`, excluded from every metric denominator) — never scored as
   wrong.
9. `softmax_t` divides by `max(1e-3, t)` and subtracts the max before exp
   (float64 on CPU paths).
10. Dataset facts to verify on first run (cheap one-liners): XNLI label names
    order; emotion label names order; ag_news label names order;
    prompt-injections label names; typed-decisions column dtypes
    (`questions`/`gold` as JSON strings, `state` as JSON string, `workflow`
    as string; 400 rows, 2000 questions total).
